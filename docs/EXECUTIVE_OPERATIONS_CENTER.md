# Executive Operations Center

Phase 6 turns the application shell into the daily operational control
center. It is a CONSUMPTION phase: every number comes from the Phase 5
Intelligence Engine (`IntelligenceSession`); operational alerts derive
from engine readiness results and pipeline states; the UI computes
nothing.

## Surfaces

| Surface | Location | What it shows |
| --- | --- | --- |
| Executive overview | `/overview` | Role-aware dashboard (below) |
| Department overview | `/departments/[id]` | Engine metrics at department scope, weekly trends, trainer/service tables |
| Trainer overview | trainer profile | Performance section (engine metrics at trainer scope, previous-period comparison) |
| Report Center | `/reports` | Quick report, saved views, export history, CSV export |
| Notification Center | `/notifications` + header bell | In-app notifications (unread/all/pinned/archived) |
| Payroll / Import overviews | `/payroll`, `/imports` + overview widgets | Pipeline lists ARE the overviews; the dashboard widgets summarize with deep links |
| Configuration overview | `/configuration` + readiness scorecard | Phase 2 hub completeness + engine readiness (overview + quick report) |

## Role-aware dashboard (one page, no duplicates)

`/overview` renders sections by CAPABILITY, so every role shares the same
widget components:

- **Trainer** (no `appointment:read`): "My operations" — self-scoped
  metric cards (the service forces trainer scope), shortcuts, no peer or
  org data anywhere.
- **Department manager** (department-scoped roles): per-department metric
  cards for exactly their departments, linking to department overviews.
- **Payroll manager / workspace admin / platform admin / viewer**: status
  cards, payroll status + open imports widgets (each gated by its
  permission), department + trainer snapshots, alerts, readiness
  scorecard + executive summary (`report:manage`), activity timeline
  (`audit:read`). Viewers simply see fewer widgets; payroll cards render
  "unavailable" for actors without `payroll:read` — the engine's
  permission answer, not a hidden section.

Offline preview and All-Workspaces retain an honest fallback (structure
plus explicit waiting states, never fabricated numbers).

## Alerts (see also WIDGET_SYSTEM / alerts.ts)

`deriveAlerts` is pure and unit-tested. Sources: intelligence readiness
results (reasons quoted verbatim) and pipeline STATES (payroll run
statuses + blocking counts, open late-arrival issues generated by the
payroll engine, import batch statuses). Each alert: severity, category,
title, engine-authored detail, recommended action, deep link, stable id,
organization. Alert "resolution" is resolving the underlying condition —
alerts disappear when the state clears; nothing is stored or duplicated.

## Performance

One batched snapshot loader per dashboard request
(`loadOperationsSnapshot`): pipeline queries in a single `Promise.all`,
one IntelligenceSession (one dataset load) shared by every widget on the
page — no widget issues its own queries, no N+1, no duplicate metric
requests. Trends and breakdowns reuse the session's already-loaded facts.

## Access control

Widgets obey three layers: capability gating in the page, permission
narrowing inside the IntelligenceSession (org / department / self /
none), and RLS on every underlying row (the snapshot loader uses the
actor's own client). Verified by the access-matrix unit tests, the alert
tests, and live Playwright (workspace switching, self scoping).
